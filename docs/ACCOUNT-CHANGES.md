## ใช้งานหลังดึงโค้ดบนอีกเครื่อง

หยุด dev server ก่อน แล้วรันในโฟลเดอร์ FixFlow:

```powershell
git pull --ff-only
npm.cmd ci
npx.cmd prisma migrate deploy
npm.cmd run dev
```

ใช้ `.env` ส่วนตัวที่เตรียมไว้บนเครื่องนั้น หากทั้งสองเครื่องเชื่อม Supabase เดียวกัน migration ที่เคยใช้แล้วจะไม่รันซ้ำ ไม่ต้องสร้างโปรเจกต์ Supabase ใหม่หรือรัน seed ซ้ำ

Migration `20261025090000_account_controls` เพิ่ม `suspendedUntil`, `suspensionReason`, ฟังก์ชันตรวจสถานะอีเมลที่เรียกได้เฉพาะ backend และข้อจำกัด Storage สำหรับบัญชีที่ถูกระงับ โดยไม่ลบข้อมูลเดิม ใช้ `DIRECT_URL` ของ owner สำหรับ migration และ `DATABASE_URL` ของ `fixflow_app` สำหรับเว็บไซต์ต่อไป

ไม่ต้องเพิ่ม secret หรือติดตั้งบริการเสียเงิน ไม่ใส่ `.env` ลง Git หากเคยเปิด Google provider ใน Supabase ให้ปิดที่ Authentication → Sign In / Providers → Google ด้วย

## ตรวจอีเมลจริงหลังอัปเดต

1. Confirm sign up ใช้ `{{ .Token }}`; Reset password ใช้ `{{ .ConfirmationURL }}` ตาม [AUTH-SETUP.md](AUTH-SETUP.md)
2. สมัครด้วยอีเมลทดสอบที่ยังไม่มีบัญชี → รับ OTP → ยืนยัน
3. ออกจากระบบ → เข้าด้วยอีเมล/รหัสผ่านเดิม ต้องเข้าได้โดยไม่ขอ OTP
4. บัญชีที่ยังไม่ยืนยันกดส่งใหม่หลังเวลารอ ใช้รหัสจากอีเมลล่าสุด
5. ถ้าส่งไม่ได้ ให้ตรวจ Supabase Auth Logs และโควตา/การยืนยันของ SMTP; การทดสอบโค้ดไม่ยืนยันการส่งถึงกล่องอีเมลจริง

## การตรวจอัตโนมัติ

- `npm.cmd test`: validation, ข้อมูลชื่อ, duplicate email, OTP resend, ล็อกอินซ้ำไม่ส่ง OTP, สิทธิ์และการระงับ
- `npm.cmd run test:accounts`: transaction จำลองบน PostgreSQL แล้ว rollback ทั้งหมด ตรวจบทบาทคงเดิม ประวัติ/รูปยังอยู่ วันหมดอายุ และสิทธิ์ฟังก์ชันค้นอีเมล
- `npm.cmd run test:profile`: บันทึกข้อมูล/รูปโปรไฟล์แบบ atomic ด้วย fixture ที่ rollback
- `npm.cmd run test:db`: ใช้เฉพาะฐานข้อมูล localhost ตรวจจองจนจบงานและตรวจว่าชื่อจองมาจาก AppUser
- `npm.cmd run build`: production build; หยุด dev server ก่อนหาก Prisma DLL ถูกล็อกบน Windows
