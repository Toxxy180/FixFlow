# ตั้งค่าอีเมล + รหัสผ่าน สำหรับ FixFlow

## ระบบที่เตรียมไว้

- `/login`: เข้าด้วยอีเมลและรหัสผ่าน ยืนยัน OTP เฉพาะตอนสมัครครั้งแรก
- `/register`: เลือกลูกค้า/ช่าง กรอกชื่อจริง นามสกุล เบอร์มือถือ อีเมล รหัสผ่านและยืนยันรหัสผ่าน แล้วกรอก OTP
- `/forgot-password`: ขออีเมล → คลิกลิงก์ → `/reset-password` → ตั้งรหัสผ่านใหม่ ใช้ตั้งรหัสผ่านครั้งแรกให้บัญชีเดิมได้ด้วย
- สมัครช่างแล้วต้องกรอกใบสมัคร แนบรูป และรอ Admin อนุมัติ ก่อนปรากฏในหน้าค้นหาและรับงาน บัญชีเป็น TECHNICIAN ตั้งแต่ยืนยันอีเมล และใช้สิทธิ์ลูกค้าไม่ได้
- ชื่อเก็บใน AppUser หลังยืนยันอีเมล รหัสผ่านจัดการโดย Supabase Auth ไม่เก็บรหัสผ่านหรือรหัส OTP ในตาราง AppUser หรือ log
- รัน `npx prisma migrate deploy` หลังอัปเดตโค้ดนี้ เพื่อเพิ่มสถานะบัญชีและตัวตรวจอีเมลซ้ำ แล้วรัน `npx prisma generate`

## 1. Supabase: เปิดอีเมลและการยืนยัน

เปิดโปรเจกต์ FixFlow → **Authentication → Sign In / Providers → Email** (ชื่อเมนูอาจแสดงเป็น Providers)

1. เปิด Email provider และอนุญาตให้สมัครสมาชิกใหม่
2. เปิด **Confirm email** เพื่อให้ต้องยืนยันอีเมลก่อนเข้าสู่ระบบ
3. ตั้งรหัสผ่านขั้นต่ำอย่างน้อย 8 ตัวอักษร หน้าเว็บกำหนดให้มีตัวอักษรภาษาอังกฤษและตัวเลขด้วย
4. ใช้ SMTP เดิมที่ตั้งสำเร็จแล้ว ไม่ต้องเปลี่ยนผู้ให้บริการ

## 2. ตั้งเทมเพลตอีเมล

เปิด **Authentication → Emails → Templates** ตั้ง **Confirm sign up** ให้แสดง OTP:

```html
<h2>รหัสยืนยัน FixFlow</h2>
<p>นำรหัสนี้ไปกรอกในเว็บไซต์ หากคุณไม่ได้ทำรายการนี้ให้ข้ามอีเมลนี้ได้</p>
<h1>{{ .Token }}</h1>
<p>อย่าส่งรหัสนี้ให้ผู้อื่น</p>
```

ส่วน **Reset password** ใช้เทมเพลตลิงก์เดิมของ Supabase ได้ หรือใช้ตัวอย่างนี้ ตั้ง subject เป็น “ตั้งรหัสผ่านใหม่ FixFlow”:

```html
<h2>ตั้งรหัสผ่านใหม่ FixFlow</h2>
<p>คลิกลิงก์ด้านล่างในเบราว์เซอร์เดียวกับที่ขอตั้งรหัสผ่าน</p>
<p><a href="{{ .RedirectTo }}?token_hash={{ .TokenHash }}">ตั้งรหัสผ่านใหม่</a></p>
<p>หากคุณไม่ได้ทำรายการนี้ ให้ข้ามอีเมลนี้ได้</p>
```

Reset password ใช้ลิงก์ TokenHash ไปที่ `/auth/recovery` เปิดข้ามเบราว์เซอร์ได้และต้องกดยืนยันก่อนใช้ token หน้า `/reset-password` รับเฉพาะ session ที่เพิ่งยืนยัน recovery สำเร็จ

เทมเพลต Magic link or OTP เดิมเก็บไว้ได้ แต่หน้าล็อกอินใหม่ไม่ได้ขอ OTP แบบไม่มีรหัสผ่านอีกแล้ว

## 3. ตั้ง URL ของเว็บ

เปิด **Authentication → URL Configuration**:

- Site URL ระหว่างพัฒนา: `http://localhost:3000`
- Redirect URLs: เพิ่ม `http://localhost:3000/auth/callback` และ `http://localhost:3000/auth/recovery`
- เมื่อ Deploy: เปลี่ยน Site URL เป็น URL จริง และเพิ่ม `https://YOUR_SITE/auth/callback` และ `https://YOUR_SITE/auth/recovery`
- ใน Vercel เพิ่ม `APP_URL=https://YOUR_SITE` โดยไม่มี path หรือ query ต่อท้าย

ในเครื่องใช้ `APP_URL="http://localhost:3000"` ตาม `.env.example` ได้ หากยังไม่ใส่ ระบบใช้ localhost:3000 เป็นค่าเริ่มต้น เมื่อแก้ env ให้เริ่ม dev server ใหม่

## 4. การตรวจอีเมลซ้ำและ OTP

- อีเมลที่ยืนยันแล้ว: แจ้งว่ามีบัญชีอยู่แล้ว ให้เข้าสู่ระบบหรือกู้รหัสผ่าน
- อีเมลที่ยังไม่ยืนยัน: ส่ง OTP สำหรับบัญชีเดิม ไม่เขียนทับชื่อหรือรหัสผ่านด้วยข้อมูลสมัครรอบใหม่
- บัญชีที่ล็อกอินแต่ยังไม่ยืนยัน: ส่งรหัส signup ใหม่ พร้อมเวลารอส่งซ้ำ
- บัญชีที่ยืนยันแล้ว: ล็อกอินด้วยรหัสผ่านได้เลย ไม่ส่ง OTP ทุกครั้ง
- การตรวจอีเมลมี rate limit ฝั่งเซิร์ฟเวอร์ และใช้ฟังก์ชันฐานข้อมูลที่ให้สิทธิ์เฉพาะ runtime role คืนเพียงสถานะ ไม่เปิดตาราง Auth ผ่าน Data API
- นำปุ่มและ server action Google ออกแล้ว หากเคยเปิด Google provider ใน Supabase ให้ปิดที่ Authentication → Sign In / Providers → Google ด้วย บัญชีเดิมยังใช้ลืมรหัสผ่านเพื่อตั้งรหัสผ่านได้

## 5. บัญชีเดิมและ Admin

บัญชีเดิม ข้อมูลช่าง รูป งานจอง และสิทธิ์ Admin ยังคงเดิม:

1. หน้า `/login` กด **ลืมรหัสผ่าน / ตั้งรหัสผ่านครั้งแรก**
2. กรอกอีเมลเดิม แล้วคลิกลิงก์ในอีเมล Reset password (ลิงก์ TokenHash ใหม่เปิดข้ามเบราว์เซอร์ได้)
3. ตั้งรหัสผ่านใหม่ จากนั้นเข้าสู่ระบบด้วยอีเมลเดิมและรหัสผ่าน
4. Admin เข้าหน้า Dashboard ลูกค้าเข้าค้นหาช่าง ช่างที่อนุมัติแล้วเข้า **งานของฉัน** ผู้สมัครช่างที่กรอกข้อมูลไม่ครบจะไปกรอกใบสมัครต่อ

ต้องยืนยัน TokenHash แบบ recovery สำเร็จ (ลิงก์เก่าผ่าน callback ต้องเป็น PASSWORD_RECOVERY) จึงออกสิทธิ์ตั้งรหัสผ่านอายุ 10 นาที ใช้ได้ครั้งเดียว การเปิด `/reset-password` เองหรือการเข้าสู่ระบบปกติไม่ให้สิทธิ์นี้ หลังตั้งสำเร็จออกจากทุก session และให้เข้าสู่ระบบใหม่

## 6. ทดสอบก่อนส่งงาน

- ลูกค้า: สมัคร → รับ OTP → ยืนยัน → ค้นหาช่าง/จองงาน
- ช่าง: สมัครเป็นช่าง → OTP → กรอกใบสมัคร/แนบรูป → รออนุมัติ → Admin ตรวจรูปและอนุมัติ → เปิดรับงาน
- กรอกรหัสผ่านไม่ตรงกัน รหัส OTP ผิด/หมดอายุ และกดส่งใหม่หลัง 60 วินาที
- ลืมรหัสผ่าน: หลังส่งแสดงคำแนะนำให้ตรวจอีเมล ไม่มีช่อง OTP ส่งลิงก์ซ้ำได้หลัง 60 วินาที ลิงก์ที่ถูกต้องเปิดหน้าตั้งรหัสผ่าน ลิงก์หมดอายุหรือใช้แล้วต้องไม่ให้เปลี่ยนรหัสผ่าน ส่วนลิงก์ TokenHash ใหม่ต้องเปิดข้ามเบราว์เซอร์ได้
- Login ผิดต้องไม่บอกว่ามีอีเมลนั้นอยู่ในระบบหรือไม่
- บัญชีเดิมตั้งรหัสผ่านครั้งแรกได้ และ Admin ยังคงเป็น Admin
- บัญชีถูกระงับต้องเข้าไม่ได้ด้วย session เดิมหรือหลังใส่รหัสผ่าน ต้องเห็นหน้าแจ้งสถานะ และทำรายการที่ต้องล็อกอินไม่ได้
- Deploy แล้วทดสอบซ้ำด้วย HTTPS และ callback URL จริง
