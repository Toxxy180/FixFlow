# อัปเดต Role, PromptPay, การโหลดข้อมูล และลืมรหัสผ่าน

1. หยุด dev server ก่อนติดตั้ง dependency และสร้าง Prisma Client
2. รัน `npm.cmd ci` และ `npx.cmd prisma migrate deploy` เพื่อเพิ่ม RegistrationIntent และข้อมูลผู้รับเงินใน Payment (migration เพิ่มโครงสร้าง ไม่ลบข้อมูลเดิม)
3. รัน `npm.cmd test`, `npm.cmd run typecheck`, `npm.cmd run build`
4. Push โค้ดเพื่อให้ Vercel Deploy ใหม่ ตัวแปร APP_URL คงเป็น `https://fix-flow-five-theta.vercel.app`

## Supabase Email Templates — Reset password

เปลี่ยนเนื้อหาเทมเพลต Reset password เป็นลิงก์นี้ โดยใช้ `.RedirectTo` ซึ่งแอปส่งเป็น URL จาก APP_URL:

```html
<h2>ตั้งรหัสผ่านใหม่สำหรับ FixFlow</h2>
<p>กดปุ่มด้านล่างเพื่อเปิดหน้าตั้งรหัสผ่านใหม่ หากไม่ได้ขอเปลี่ยนรหัสผ่าน ให้ละเว้นอีเมลนี้</p>
<p><a href="{{ .RedirectTo }}?token_hash={{ .TokenHash }}">ตั้งรหัสผ่านใหม่</a></p>
```

เพิ่ม Redirect URL `https://fix-flow-five-theta.vercel.app/auth/recovery` และ `http://localhost:3000/auth/recovery` ใน Supabase Authentication > URL Configuration โดยเก็บ `/auth/callback` เดิมเพื่อรองรับลิงก์เก่า ปิด link tracking ของผู้ให้บริการ SMTP หากเปิดอยู่

ลิงก์ใหม่เปิดได้ข้ามเบราว์เซอร์ หน้าแรกของลิงก์ยังไม่ใช้ token จนผู้ใช้กดดำเนินการ จากนั้น server ตรวจ token ด้วย Supabase type=recovery และออก recovery ticket อายุ 10 นาที ลิงก์เดิมแบบ PKCE ยังต้องเปิดในเบราว์เซอร์ที่ขอ หากลิงก์เดิมหมดอายุให้ขออีเมลใหม่หลังปรับเทมเพลต

Confirm sign up ยังคงใช้ `{{ .Token }}` สำหรับ OTP สมัครสมาชิก

## บัญชีและการชำระเงิน

- ผู้สมัครใหม่ต้องกรอกเบอร์มือถือไทยและเลือก CUSTOMER หรือ TECHNICIAN บทบาทบันทึกฝั่ง server ใน RegistrationIntent ไม่ใช้ user_metadata เป็นสิทธิ์
- CUSTOMER และ ADMIN ส่งใบสมัครช่างไม่ได้ TECHNICIAN ต้องส่งข้อมูลและรออนุมัติจึงเปิดรับงานได้ และใช้สิทธิ์ลูกค้าไม่ได้
- บัญชีเดิมคงบทบาทเดิมและประวัติทั้งหมด บัญชีลูกค้าที่เคยส่งใบสมัครช่างตามระบบเดิมไม่ถูกเปลี่ยนบทบาทอัตโนมัติ ต้องใช้บัญชีช่างแยกสำหรับการทดสอบระบบใหม่
- เมื่อเปิด QR ครั้งแรก ระบบเก็บเบอร์ผู้รับจากบัญชีช่างเจ้าของงานและชื่อไว้ใน Payment ใช้ยอดงานรวมอะไหล่จาก server ลูกค้าแก้ผู้รับ/ยอดในคำขอไม่ได้
- ช่างต้องมีบัญชีผู้ใช้ที่เชื่อมกับงานและเบอร์ที่ผูก PromptPay ช่างตัวอย่างที่ยังไม่มีบัญชีผู้ใช้จะไม่สร้าง QR ให้แทนด้วยเบอร์อื่น
- QR โอนได้จริงผ่านแอปธนาคาร แต่แอปไม่ตรวจยอดโอนหรือสลิป ปุ่มยืนยันทำเครื่องหมาย PROMPTPAY_DEMO และระบุว่าเป็นสถานะจำลอง

## ประสิทธิภาพ

รายการช่างใช้ query เดียวรวมข้อมูลที่เปิดเผยได้ คำนวณค่าเฉลี่ยรีวิวใน PostgreSQL แทนการส่งรีวิวทุกแถวมาที่ server แคชรายการและค่าตั้งค่า 30 วินาที และล้างแคชเมื่อแก้ข้อมูลผ่านแอป ไม่แคช session/สิทธิ์/งานส่วนตัว การทำรายการตรวจสิทธิ์และข้อมูลฐานข้อมูลล่าสุดอีกครั้ง

vercel.json เลือก Tokyo ให้ใกล้ Supabase โปรเจกต์ปัจจุบัน หากย้ายฐานข้อมูลไปภูมิภาคอื่นต้องปรับ region ให้ตรงกัน
