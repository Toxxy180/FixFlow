# ผลตรวจ FixFlow — 14 ตุลาคม 2026

- Unit tests 6 ข้อ: ราคา วันที่และเวลาไทย การตรวจ input สิทธิ์เปลี่ยนสถานะ redirect และการปิด demo ใน production
- PostgreSQL integration tests 2 ข้อ: สถานะ RLS ทั้ง 15 ตาราง และขั้นตอนจอง/สิทธิ์/ราคาคงเดิม/เวลาซ้ำ/ยกเลิก/อะไหล่/ชำระเงินจำลอง/รีวิว
- ตรวจ TypeScript และ production build
- Browser: ลูกค้าจองงาน → ช่างรับงาน/เดินทาง/เริ่มงาน/เพิ่มอะไหล่/แจ้งยอด → ลูกค้าชำระเงินจำลองและรีวิว
- Browser: Admin เพิ่ม แก้ไข และปิดบริการ; แก้ค่าเดินทาง บันทึกและโหลดซ้ำได้ แล้วคืนค่าตัวอย่างเดิม
- Browser รอบล่าสุด: สลับบัญชีลูกค้า/Admin, เปิด Dashboard และตั้งค่า, โหลดเวลาว่าง และปฏิเสธลูกค้าที่เข้า `/admin`
- Responsive: 1536×1024 และ 390×844; เมนูมือถือ ฟอร์มเลื่อนภายใน และหน้าไม่ล้นขอบจอ

แก้ในรอบสุดท้าย: แสดงข้อความตารางว่างให้ครบในมือถือ เพิ่มชื่อที่อ่านได้ให้เมนูบัญชี และปรับฐานข้อมูลทดลองเป็น IPv4 + connection_limit=1 หลังพบ local proxy ตัดการเชื่อมต่อเมื่อใช้หลาย connection พร้อมกัน ทดสอบต่อด้วยหน้าเว็บและ integration tests แล้วผ่าน

## เทียบกับภาพแนวทางออกแบบ

1. โครงหน้า: login สองคอลัมน์ และ Admin มี sidebar, metrics, ตาราง และลิงก์จัดการตามภาพ
2. ลำดับเนื้อหา: หัวเรื่องเด่น ฟอร์มและข้อมูลสำคัญอ่านก่อนส่วนรอง
3. ตัวอักษร: ใช้ Noto Sans Thai จริง ขนาดข้อความฟอร์มกระชับกว่าภาพแนวทาง
4. สีและเส้นขอบ: พื้นขาว/เทาอ่อน ตัวอักษรกรมท่า ปุ่มน้ำเงิน เส้นขอบบางสอดคล้องกัน
5. ไอคอนและรายละเอียด: ใช้ Lucide SVG; เพิ่มแถบและปุ่มทดลองเฉพาะ development และใช้ตัวเลขจากฐานข้อมูลจริง

ภาพแนวทางอยู่ใน `docs/admin-concept.png` และ `docs/login-concept.png` ส่วนหลักฐาน browser อยู่ในโฟลเดอร์ visualizations ของแชทนี้

## ยังต้องตรวจเมื่อมีโปรเจกต์จริง

- ส่ง/รับ Email OTP จริง รหัสผิด หมดอายุ ส่งใหม่ และ session refresh กับ Supabase
- Runtime role และ RLS policy บน Supabase จริง (รอบนี้ตรวจ metadata RLS แบบอ่านอย่างเดียว)
- Vercel environment variables, HTTPS, production URL และ OTP หลัง Deploy
- การชำระเงินในโครงการนี้เป็นแบบจำลอง ไม่ได้เชื่อมธุรกรรมธนาคาร

ปุ่มทดลองใช้ได้เฉพาะ development และฐานข้อมูลในเครื่อง ยังไม่ได้นำเว็บขึ้นออนไลน์
