# เชื่อม Supabase และ Deploy FixFlow

เวอร์ชันนี้ใช้ Next.js 16 + Prisma 6.19 + Tailwind 4, PostgreSQL และ Supabase Auth แบบอีเมล/รหัสผ่าน โดยใช้ OTP ยืนยันสมัครสมาชิกครั้งเดียว และใช้ลิงก์อีเมลกู้รหัสผ่าน

## 1. สร้างโปรเจกต์ Supabase

สร้างโปรเจกต์ `fixflow` และเก็บรหัสฐานข้อมูลใน password manager เลือก region ที่เหมาะกับผู้ใช้ไทย

ในเมนู **Connect** คัดลอก Session pooler และ Transaction pooler จากโปรเจกต์จริง ห้ามเดาชื่อ host

- Session pooler พอร์ต 5432 ใช้เป็น `DIRECT_URL` สำหรับ migration และรองรับ IPv4
- Transaction pooler พอร์ต 6543 ใช้เป็น `DATABASE_URL` สำหรับ Vercel เพิ่ม `pgbouncer=true&connection_limit=5&sslmode=require`
- ถ้ารหัสผ่านมีอักขระพิเศษ ต้อง URL-encode เฉพาะส่วนรหัสผ่าน

เริ่มตั้งค่าใน `.env` ตาม `.env.example` ก่อน bootstrap ใช้ database owner สำหรับทั้งสอง URL ได้ชั่วคราว แล้วเปลี่ยน DATABASE_URL เป็น runtime role ตามขั้นตอน 3 ก่อน deploy

```dotenv
DATABASE_URL="ค่าการเชื่อมต่อฐานข้อมูล"
DIRECT_URL="ค่าการเชื่อมต่อสำหรับ migration"
NEXT_PUBLIC_SUPABASE_URL="Project URL"
NEXT_PUBLIC_SUPABASE_PUBLISHABLE_KEY="Publishable key"
DEMO_AUTH="false"
```

ไฟล์ `.env` ถูก gitignore และใช้ร่วมกันโดย Next.js, Prisma และ scripts ไม่ต้องสร้าง `.env.local` ซ้ำ หากมีไฟล์ `.env.local` เดิมให้ตรวจค่าให้ตรงกัน เพราะ Next.js ให้ไฟล์นั้นมีลำดับความสำคัญสูงกว่า

## 2. สร้างตารางและข้อมูลเริ่มต้น

```powershell
npm install
npm run db:setup
```

ใช้ `prisma migrate deploy` กับ migration PostgreSQL ที่แนบมา ไม่ใช้ `migrate reset` หรือ SQLite migration เดิมกับ Supabase

Seed มี 50 เขต ช่างตัวอย่าง 6 คน หมวดหมู่ บริการ และ config โดยไม่สร้างบัญชี Admin ออนไลน์ และไม่เขียนทับข้อมูลที่ Admin เคยแก้

รอจนเห็นข้อความ `สำเร็จ: ข้อมูลตั้งต้นครบ...` และ Terminal กลับมารอคำสั่งก่อนเปิดเว็บ ข้อความ `All migrations have been successfully applied` ยืนยันเฉพาะการสร้างตาราง หากเคยปิดคำสั่งก่อน seed เสร็จ ให้รัน `npm run db:seed` เพื่อเติมข้อมูลที่ขาดได้ Seed ใช้ transaction และไม่เขียนทับข้อมูลเดิม

ตารางข้อมูลแอปเปิด RLS และไม่มีสิทธิ์ให้ `anon`/`authenticated` เข้าถึงตรงผ่าน Data API การอ่านและแก้ไขทำผ่าน Next.js + Prisma พร้อมตรวจสิทธิ์ทุกครั้ง

## 3. สร้าง runtime database role

เปิด SQL Editor และใช้ `docs/runtime-role.sql` โดยเปลี่ยนรหัสผ่านในเครื่อง/SQL Editor ไม่บันทึกรหัสจริงลง Git

Role `fixflow_app` ไม่มีสิทธิ์ superuser, bypassrls หรือสร้าง schema มีสิทธิ์เฉพาะตารางของ FixFlow และ RLS policy สำหรับ backend นี้

เปลี่ยน USER ใน Transaction pooler ของ `DATABASE_URL` เป็น `fixflow_app.PROJECT_REF` และใช้รหัสของ role นี้ ส่วน `DIRECT_URL` ใช้ database owner สำหรับ migration ต่อไป

## 4. ตั้ง Supabase Auth / Password + Signup OTP

**ระบบบัญชีรุ่นใหม่:** ทำตาม [AUTH-SETUP.md](AUTH-SETUP.md) สำหรับหน้าสมัครแยกลูกค้า/ช่าง การยืนยัน OTP การตั้งรหัสผ่านครั้งแรกของบัญชีเดิม และการส่ง OTP ซ้ำ ตั้งเทมเพลต **Confirm sign up** เป็น `{{ .Token }}` และ **Reset password** เป็นลิงก์ `{{ .ConfirmationURL }}` และเพิ่ม `APP_URL` เป็น URL จริงใน Vercel

1. เปิด Email provider และใช้การยืนยันอีเมล
2. ตั้ง custom SMTP ให้เรียบร้อยก่อนแก้เทมเพลต หากต้องการใช้งานฟรีสำหรับสาธิต ใช้บัญชี Gmail ที่เปิดการยืนยัน 2 ขั้นตอนและสร้าง App Password ได้: Host `smtp.gmail.com`, Port `465`, Sender email และ Username เป็นอีเมลบัญชีเดียวกับที่สร้าง App Password, Password เป็น App Password 16 ตัวโดยตัดช่องว่างออก เก็บรหัสไว้เฉพาะ Supabase SMTP Settings ไม่ใส่ใน Git หรือแชท บัญชีสถาบันอาจถูกจำกัดโดยผู้ดูแล และ Gmail มีโควตาการส่ง
3. ใน Email Templates ปรับทั้ง **Confirm sign up** และ **Reset password** ให้มี `<h1>{{ .Token }}</h1>` แทนปุ่มลิงก์ แล้วบันทึกทั้งสองเทมเพลต
4. ตั้งอายุ OTP ให้เหมาะกับการสาธิต เช่น 10 นาที ตั้ง resend/rate limits ให้สอดคล้องกับการใช้งาน หากเลือก Resend ต้องใช้โดเมนผู้ส่งที่ยืนยันแล้ว
5. กำหนด Site URL เป็น URL เว็บจริง และ allowlist redirect ของ localhost/production ที่ใช้เท่านั้น
6. ปิด email-link tracking ของ SMTP provider หากเปิดใช้อยู่

SMTP เริ่มต้นของ Supabase จำกัดผู้รับเป็นสมาชิกในทีมโปรเจกต์ จึงต้องใช้ custom SMTP หากอาจารย์หรือผู้ใช้นอกทีมจะรับรหัส

หน้า login ใช้อีเมล/รหัสผ่านโดยไม่ขอ OTP ซ้ำ ส่วนหน้าสมัครมีขั้นกรอก OTP และส่งรหัสใหม่ได้หลัง cooldown การกู้รหัสผ่านใช้ลิงก์อีเมล ระบบใช้ `getUser` ตรวจ session ฝั่ง server พร้อม Proxy refresh cookie

ไม่มี service-role key ใน browser และไม่ต้องตั้ง service-role key สำหรับการทำงานปกติ

## 5. ตั้ง Admin คนแรก และบัญชีช่าง

เข้าสู่ระบบด้วยอีเมลของคุณและยืนยัน OTP ให้สำเร็จก่อน จากนั้นในเครื่องที่มี `.env` ของ Supabase:

```powershell
npm run admin:grant -- YOUR_VERIFIED_EMAIL
```

หลังเข้าสู่ระบบ Admin เข้าหน้า `/admin` ลูกค้าเข้าหน้าค้นหาช่าง `/` และช่างที่อนุมัติแล้วเข้าหน้า `/technician` เมนูหลักของ Admin มีเฉพาะ **ค้นหาช่าง** และ **แดชบอร์ดจัดการระบบ** ลูกค้ามี **ค้นหาช่าง** และ **การจองของฉัน** ส่วนช่างมี **ค้นหาช่าง** และ **งานของฉัน** เมื่อช่างเปิด `/bookings` ระบบพาไป `/technician` อัตโนมัติ

ลูกค้ากดชื่อหรือรูปบัญชีมุมขวาบนเพื่อเปิดเมนู **สมัครเป็นช่าง / เปิดรับงาน** หรือเปิด **บัญชีของฉัน** แล้วขยายตัวเลือกเดียวกัน กรอกใบสมัครที่ `/technician/apply` ด้วยชื่อ เบอร์โทร ประเภทบริการ ราคา เขต วันและเวลารับงาน ระบบสร้างโปรไฟล์ที่ยังไม่เปิดรับงานและคงสิทธิ์ CUSTOMER ไว้ระหว่างรอ จึงยังจองบริการได้ สถานะรออนุมัติแสดงในหน้าบัญชี หลังอนุมัติเข้าจัดการงานจากเมนูบัญชี **งานของฉัน** ได้

Admin เปิด `/admin/technicians` ตรวจรายการ **รออนุมัติ** แล้วกด **อนุมัติและเปิดรับงาน** ระบบเปลี่ยนสิทธิ์เป็น TECHNICIAN และเปิดโปรไฟล์พร้อมกัน บัญชีช่างใช้รับงานและจัดการงานของตัวเอง ไม่แสดงปุ่มจองใหม่และไม่อนุญาตให้สร้างรายการจองฝั่งลูกค้า สำหรับรายการที่เคยจองไว้ก่อนเปลี่ยนเป็นช่าง สิทธิ์ดูรายละเอียดและจัดการรายการเดิมยังแยกตามเจ้าของงาน

### รูปโปรไฟล์และรูปใบสมัครช่าง

หลังอัปเดตโค้ด รัน `npx prisma migrate deploy` และ `npx prisma generate` (หยุด dev server ก่อนหาก Windows แจ้งว่าไฟล์ Prisma ถูกล็อก) จากนั้นเปิด Supabase SQL Editor และรัน `docs/storage-setup.sql` หนึ่งครั้งเพื่อสร้าง bucket และ policy ไม่ต้องเพิ่ม service-role key และไม่ต้องเปิด Data API สำหรับตารางแอป

- `fixflow-avatars` เป็น public bucket สำหรับรูปโปรไฟล์ที่แสดงบนเว็บ
- `fixflow-portfolios` เป็น private bucket เจ้าของและ Admin ที่บัญชียังเปิดใช้งานเท่านั้นที่เปิดรูปผ่านเว็บได้ ลิงก์ดูรูปมีอายุ 5 นาที
- อัปโหลด JPG/PNG/WebP ไม่เกิน 2 MB ต่อรูป ระบบตรวจเนื้อไฟล์ ย่อรูป แปลง WebP และลบ EXIF ก่อนจัดเก็บ
- ลูกค้า ช่าง และ Admin เปลี่ยน/ลบรูปโปรไฟล์ของตัวเองจาก **บัญชีของฉัน** ได้ รูป ชื่อ และเบอร์โทรใช้ปุ่ม **บันทึกข้อมูล** ปุ่มเดียว การเลือกรูปแสดงตัวอย่างก่อน กด **ยกเลิก** จะคืนค่าทั้งรูป ชื่อ และเบอร์โทรโดยไม่อัปโหลด การออกจากหน้าก่อนบันทึกจะคงข้อมูลเดิมไว้ รูปของช่างแสดงในหน้าค้นหาด้วย
- ผู้สมัครช่างแนบรูป 1–5 รูป และลิงก์ผลงาน/เพจแบบ http(s) เพิ่มได้ ผู้สมัครอ้างรูปของบัญชีอื่นไม่ได้
- Admin เข้า **จัดการช่าง → คำขอสมัครเป็นช่าง → ดูรายละเอียดคำขอ** เพื่อตรวจข้อมูลติดต่อ รูป ลิงก์ พื้นที่ และตารางเวลา แล้วอนุมัติหรือส่งกลับพร้อมเหตุผล รายการคำขอแสดงเฉพาะสถานะรอตรวจสอบ เมื่ออนุมัติแล้วช่างจะอยู่ในรายการจัดการช่างด้านล่าง
- ผู้สมัครดูเหตุผลและแก้ไขส่งใหม่จากหน้าบัญชีได้ ขณะรออนุมัติยังเป็น CUSTOMER และโปรไฟล์ยังไม่แสดงบนหน้าค้นหา
- รูปในใบสมัครที่อนุมัติแล้วแก้ผ่านผู้ดูแล ส่วนรูปในใบสมัครที่ยังรอ/ส่งกลับแก้ไขลบได้ โดยระบบตรวจความครบถ้วนอีกครั้งก่อนอนุมัติ

โควตาอัปโหลดผ่านแอป 30 ครั้งต่อบัญชีต่อชั่วโมง รูปใบสมัครเก็บได้สูงสุด 5 รูปต่อบัญชี การย่อรูปช่วยลดพื้นที่และ bandwidth ของแพ็กเกจฟรี แต่ยังต้องใช้งานภายในโควตา Supabase ของโปรเจกต์

หลังตั้ง Admin คนแรกแล้ว เข้าสู่ระบบใหม่หรือเปิด `/login` เพื่อเข้าหน้าแดชบอร์ดทันที เมนู **แดชบอร์ดจัดการระบบ** เปิดได้ตลอดจากแถบด้านบน บัญชีทั่วไปไม่มีปุ่มสมัคร Admin และไม่สามารถเข้าเส้นทาง `/admin` ได้ หน้า Admin จัดการผู้ใช้ บริการ ช่าง รายการจอง และคอนฟิกได้ เส้นทาง `/choose-role` เดิมเปลี่ยนให้พา Admin ไป `/admin` และผู้ใช้ทั่วไปไป `/account` เพื่อรองรับลิงก์เก่า

ผู้ใช้ใหม่เป็น CUSTOMER เสมอ role ไม่อ่านจาก user metadata และผู้ใช้ไม่สามารถกำหนด Admin ให้ตัวเองผ่านหน้าเว็บ

การบันทึกผู้ใช้หรือระงับบัญชีจะคงใบสมัคร รูป และประวัติที่ผูกกับช่างไว้ ผู้สมัครสถานะรอตรวจ/ส่งกลับต้องผ่านปุ่มอนุมัติในหน้าจัดการช่างก่อน ไม่เปลี่ยนเป็นช่างตรงจากหน้าผู้ใช้ เมื่อบัญชีกลับมาใช้งานได้ ช่างที่ได้รับอนุมัติและเปิดรับงานไว้จะปรากฏอีกครั้ง ส่วนช่างที่ปิดรับงานหรือยังไม่ผ่านอนุมัติจะยังไม่เปิดรับงาน

ทดสอบการจัดการบัญชีด้วย `npm run test:accounts` ได้หลังตั้งฐานข้อมูลแล้ว ใช้ข้อมูลจำลองใน transaction และ rollback ทั้งหมดแม้ทดสอบไม่ผ่าน ไม่ส่ง OTP ไม่สร้างบัญชี Supabase Auth และไม่อัปโหลดไฟล์

หากปุ่มจองยังบันทึกไม่ได้ ให้เลือกวันที่ในอนาคตและช่วงเวลาที่ว่าง ใช้ชื่อจากบัญชี กรอกเบอร์โทร 10 หลัก เขต และที่อยู่อย่างน้อย 10 ตัวอักษร หน้าจองจะแจ้งกรณีวันหยุด เวลาผ่านไปแล้ว/เต็ม หรือโหลดเวลาไม่สำเร็จ พร้อมปุ่มโหลดเวลาอีกครั้ง

## 6. Deploy บน Vercel

1. Push โปรเจกต์ขึ้น GitHub โดยไม่ commit `.env` หรือฐานข้อมูลเดิม
2. Import repository ใน Vercel เลือก Next.js และ Node.js 22 หรือ 24
3. ใส่ environment variables ทั้งห้าค่าจากขั้นตอน 1 กำหนด `DEMO_AUTH=false` และเพิ่ม `APP_URL` เป็น HTTPS URL ของเว็บจริงสำหรับลิงก์กู้รหัสผ่าน
4. ก่อน Deploy รันในเครื่อง:

```powershell
npm run check:deploy
npm test
npm run typecheck
npm run build
```

5. ใช้ Build Command `npm run build` ซึ่งมี `prisma generate` แล้ว
6. เมื่อ deploy ได้ URL ให้อัปเดต Site URL/redirect settings ใน Supabase และทดสอบ OTP จาก URL จริง
7. หากใช้ custom domain ตั้ง DNS ตาม Vercel แล้วอัปเดต Supabase URLs อีกครั้ง

ไม่รัน migration/seed อัตโนมัติในทุก Preview build เพื่อลดการเปลี่ยนฐานข้อมูล production โดยไม่ตั้งใจ สำหรับการแก้ schema ครั้งต่อไปให้รัน `npm run db:setup` เป็น release step ก่อน deploy และตรวจ migration ก่อนใช้งาน

Preview และ Production ควรใช้ Supabase projects คนละชุด หลีกเลี่ยง Preview ที่เขียนข้อมูลจริง

## 7. ตรวจงานก่อนส่ง

- ลูกค้า: ส่ง OTP / รหัสผิด / รหัสหมดอายุ / ส่งใหม่ / logout
- ลูกค้าเลือกเขตและบริการ จองเวลาว่าง ดูประวัติ และยกเลิกก่อนเวลาที่กำหนด
- ลองจองช่างเดียวกันเวลาเดียวกันจากสองบัญชี ต้องสำเร็จเพียงรายการเดียว
- ช่างเห็นเฉพาะงานตัวเอง รับงาน เดินทาง เริ่มงาน เพิ่มอะไหล่ ส่งยอดเรียกเก็บ
- ลูกค้ายืนยันการชำระเงินจำลอง แล้วรีวิวได้เพียงครั้งเดียว
- Admin เพิ่ม/แก้/ปิดใช้งานข้อมูล ตั้งค่า และดูประวัติการแก้ไข
- ลูกค้าเข้า `/admin` หรือดูงานของคนอื่นไม่ได้
- ทดสอบมือถือและตรวจยอดรวม/เวลาประเทศไทย

การชำระเงินในรุ่นนี้เป็นแบบจำลอง ไม่มี Payment Gateway, PromptPay จริง หรือการตรวจสลิปอัตโนมัติ
